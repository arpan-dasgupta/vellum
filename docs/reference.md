# Vellum reference

The details behind the [README](../README.md): shortcuts, the annotation tools, the document format, batch export and the annotation data an agent reads.

## Keyboard shortcuts

| Action | Keys |
| --- | --- |
| Move, hand | V, H |
| Rectangle, ellipse | R, O |
| Text, connector | T, C |
| Pen, arrow, highlight, note | P, A, M, N |
| Arrow, highlight from any tool | Right-drag, right-click |
| Group, ungroup | ⌘G, ⇧⌘G |
| Combine selected annotations | ⌘G |
| Duplicate | ⌘D |
| Bring forward, send backward | ⌘], ⌘[ |
| Hide, lock | ⇧⌘H, ⇧⌘L |
| Zoom to fit, zoom to selection, 100% | ⇧1, ⇧2, ⇧0 |
| Undo, redo | ⌘Z, ⇧⌘Z |

Double-click steps into a group, and ⌘-click selects the deepest layer. On phones the tools move to a floating bar, and two-finger pinch zooms.

## Annotations

Annotations live in their own "Annotations" layer on each page, in five colours.

- **Sketches.** While the pen is active, every stroke joins one sketch, so a drawing of several strokes is one annotation. Press Done or Esc to finish it, or New sketch to start another. A sketch means "I want something like this" by default. Switch it to "Points at something" when it only marks a spot.
- **Arrows.** Ends stick to the layer under them. Small layers snap to their centre, and big ones keep the exact point. Hold Alt for a free end.
- **Highlights.** Click to highlight the most specific layer under the pointer, or drag to highlight an area.
- **Notes.** Sticky notes whose text is the instruction.
- **Combining.** Select several annotations and press ⌘G to make them one annotation with one thread.
- **Threads.** Select an annotation to add follow-ups, and resolve it when the work is done. A follow-up on a resolved annotation reopens it. Resolved annotations are hidden from the canvas and from exports, and stay listed under Resolved in the side panel.

## Document format

Documents are plain JSON. Open and save them from the File menu. The current document autosaves to `localStorage`.

```json
{
  "version": 1,
  "name": "Untitled",
  "pages": [
    { "id": "page-1", "name": "Page 1", "children": [
      { "id": "r1", "type": "RECT", "name": "Box", "x": 0, "y": 0, "w": 100, "h": 100, "fill": "#D9D9D9" }
    ] }
  ]
}
```

Every node has an `id`, a `type` and a `name`, and uses absolute page coordinates.

| Type | Fields |
| --- | --- |
| `RECT`, `ELLIPSE` | `x y w h fill fillOpacity stroke strokeWidth radius` |
| `TEXT` | `x y text fontSize fontWeight color lineHeight align autoWidth w`, plus optional coloured `runs` |
| `PATH` | `x y w h vw vh fill stroke detail strokeWidth paths[{d, role}]`, where `role` is `body`, `ink` or `dot` |
| `GROUP` | `children`; its bounds come from the children |
| `SECTION` | `x y w h fill stroke radius children` |
| `CONNECTOR` | `from{id, side} to{id, side} label stroke strokeWidth dash arrow headSize` |
| `IMAGE` | `x y w h src`, where `src` is a data URI. Animated GIFs play on the canvas. |
| `INK` | `strokes[{points, stroke, strokeWidth}] intent`, a sketch whose `intent` is `mockup` or `mark` |
| `STICKY` | `x y w h text fill fontSize`, a note whose height grows with its text |

A document generated by a script can also carry two top-level fields:

- `sample`, a tag naming the document;
- `sampleVersion`, its version number.

When the starting document has a higher `sampleVersion` than an autosaved copy with the same tag, the editor loads the new version. The old copy stays one undo away.

## The starting document

`vellum.config.json` names the document the editor opens when there is no autosaved copy. File › Load reopens it.

```json
{ "startDocument": "diagrams/fog-of-war/fog-of-war.json" }
```

## Batch export

With `tools/devserver.py` running, `export.html?jobs=<jobs.json>` renders layers to SVG and PNG in the browser and saves them:

```json
{
  "doc": "my-diagram.json",
  "out": "exports",
  "jobs": [
    { "nodes": ["section-1"], "file": "overview", "pad": 0, "scale": 1 },
    { "nodes": ["panel-3"], "file": "panel-3", "pad": 24, "bg": "#F9F9F9", "scale": 2 }
  ]
}
```

- **Paths.** `doc` and `out` are relative to the jobs file.
- **Output.** Each job writes `<out>/<file>.svg` and `<out>/<file>.png`, with optional padding, background and PNG scale.
- **Fonts.** SVGs embed the Inter font when it can be fetched.

`export.html?review=<annotations.json>` renders each open annotation on its own, cropped around it, into `.tmp/review/`. Add `&bare=1` to render the same crops without the annotations.

The dev server only saves `.svg`, `.png`, `.gif` and `.json` files inside a folder named `exports` or under `.tmp/`.

## Annotation data

When Vellum runs as a Claude artifact with the `db` capability, each page's annotations sync to the database as `annotations/<pageId>`. Run anywhere else, they stay in the browser's autosave and in saved files.

The synced document holds:

- `pageId`, `pageName`, `updatedAt`, `count` and `open`.
- `summary`, one plain-language line per annotation.
- `items`, the annotation nodes. Each one also carries:
  - `about`, a plain-language line saying what it is and what it points at, such as "red sketch of what the user wants (1 stroke, 349 × 101) over “Next-state predictions”";
  - `status`, which is `"resolved"` when done;
  - `resolvedBy` and `resolvedAt`;
  - `replies`, a list of `{id, author, text, at}` where `author` is `user` or `claude`.

## Scripting

In the browser console, `window.vellum` exposes `doc`, `selection`, `select(ids)`, `mutate(fn)` and `exportSVG(ids, opts)`.

## Code layout

- **The editor.**
  - `core.js` holds the document model, text layout, bounds, SVG rendering and export. It has no DOM dependency apart from an injected text measurer, so the editor and the render pages share it.
  - `app.js` is the editor UI: tools, selection, panels, history, files and annotation sync.
  - `index.html` holds the markup and styles.
- **The render page.** `export.html` runs batch export and annotation review.
- **Tools.** `tools/devserver.py` is a static server with a save endpoint. `tools/make_gif.py` packs PNG frames into an animated GIF with only the Python standard library.
